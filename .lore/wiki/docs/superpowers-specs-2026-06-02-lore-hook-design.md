# post-commit hook — 耐久捕获地板（§4①）

> 设计文档 (spec) · 2026-06-02 · 子项目 **post-commit hook（§4① 捕获源）** · 已 brainstorm 收敛，待转计划

## 0. 背景
mine 是**手动** bootstrap 回填。hook 是**自动地板**：每 commit 机械写一条骨架原子，即使 agent 没跑 / 上下文被压都不丢（母 §4① 抗压缩地板）。本质 = 「mine 但只挖刚 commit 的 HEAD」。母 §6 line 359 明确：hook 是 lore 零侵入的**唯一例外**（git 机制非业务源码，只追加捕获骨架）。

## 1. 范围
- `lib/hook.js`（新）：单 commit 捕获 runtime。**纯机械、零 LLM/网络、<50ms、best-effort（永远 exit 0 不阻断 commit）**。
- 扩 `lib/init.js`：装 hook（策略 A）+ config `journal.hook` `false→true`。
- 改 `commands/lore-init.md`：注明装 hook。
- 小改 `lib/mine.js`：`export` 现有 `GIT_FORMAT` const + `commitAtom` 加 `source` 参（default 不变，供 hook 复用）。

**推迟**：flow/theme facet（同 mine，component-only）· chain 已有 hook · core.hooksPath 安装 · enrich。

**核心不变量（母 §6）**：lore 只写 `.lore/` + 一个 post-commit hook（唯一 .git 例外）。卸载 = 删 `.lore/` + 摘 hook，业务源码丝毫不动。

## 2. hook runtime（`lib/hook.js`）
`captureHead({ repoRoot, journalDir, codeRoots }) -> { added }`（导出，可测）：
- `git log -1 --no-merges --pretty=format:${GIT_FORMAT} --name-only HEAD` → `parseGitLog`（复用 mine）→ raws。
- raws 空（HEAD 是 merge → --no-merges 跳到祖先；或空 repo）→ `{added:0}`，不写。
- `commitAtom(raws[0], codeRoots, 'hook')`（复用 mine；**给 commitAtom 加 `source` 参数**，default `'miner:commits'`，hook 传 `'hook'` → §4① 要求 hook 原子 `source=hook` 区分捕获源）→ atom。`existingIds(journalDir)`（复用 journal）含 atom.id（mine 可能已挖）→ skip `{added:0}`；否则 `appendAtom` → `{added:1}`。

`lib/mine.js` 小改：`commitAtom(raw, codeRoots, source = 'miner:commits')` 加第三参；现有 mine 调用走 default 不变（其测试断言 `source==='miner:commits'` 仍过）。

CLI `node lib/hook.js <repoRoot>`：读 config code_roots（`parseConfigCodeRoots`），journalDir=`<repoRoot>/.lore/journal`，调 captureHead，**全 try/catch 吞错 + `process.exit(0)`**（§4① 硬约束：失败 best-effort 不阻断 commit）。

性能：单 `git log -1` + 路径前缀映射 + 一次 append，无 LLM/网络 → <50ms。

**merge 边界**：`git log -1 --no-merges HEAD` 在 merge HEAD 时返回最近非 merge 祖先（已挖 → 去重跳过 → 无新原子，符合「merge 不产原子」意图）。可接受。

## 3. install（扩 init 的 `installHook(repoRoot) -> string`）
返回状态串之一：`installed | present | exists-foreign | hookspath-set | no-git`。
- 无 `<repoRoot>/.git/` → `no-git`（非 git repo，init 其余照做）。
- `git config --get core.hooksPath` 设了（husky）→ `hookspath-set`（不装 + 警告：装进默认 .git/hooks 会被绕过）。
- `.git/hooks/post-commit`：
  - 已存在含 marker `# lore:post-commit` → `present`（幂等 skip）。
  - 已存在（非 lore）→ `exists-foreign`（**不覆盖** + 警告让用户手动加）。
  - 不存在 → 写 stub + `chmodSync(0o755)`（best-effort）→ `installed`。

**stub 内容**（绝对路径装时烘焙；hook 在 Claude 外跑无 `${CLAUDE_PLUGIN_ROOT}`；**路径转 forward-slash**保 sh 在 Windows 安全）：
```sh
#!/bin/sh
# lore:post-commit (auto-generated by /lore:init)
node "<plugin>/lib/hook.js" "$(git rev-parse --show-toplevel)" >/dev/null 2>&1 || true
```
`<plugin>/lib/hook.js` = `join(dirname(fileURLToPath(import.meta.url)), 'hook.js')` 再 `.replace(/\\/g, '/')`。`|| true` 双保险不阻断 commit。

`init({repoRoot, srcSiteDir})`：在 ensureGitignore 后调 `installHook`，结果纳入 report（`hook: <状态>`）。`renderConfigYaml` 的 `journal.hook` 从 `false` 改 `true`（init 现真装）。

## 4. 命令改（`commands/lore-init.md`）
删「本版不安装 post-commit hook」类旧话；加：init 现装 post-commit hook（每 commit 自动写 journal 骨架原子；已有 hook / core.hooksPath / 非 git 则 skip 并提示）。

## 5. 测试（确定性 node:test）
- **`captureHead`**：临时 git repo + 一个碰 code_root 的 commit → captureHead → journal 有该 commit 原子（component 对、**source=hook**）；**幂等**（再调 added:0）；**merge HEAD** → added:0（不产新）；空/坏 → 不崩。
- **`installHook`**：临时 git repo → `installed` + `.git/hooks/post-commit` 含 marker + 调 hook.js（forward-slash 路径）；重调 → `present`；预置非 lore hook → `exists-foreign` 不覆盖；`git config core.hooksPath X` → `hookspath-set`；非 git 目录 → `no-git`。
- **`renderConfigYaml`**：`hook: true`。
- **init 集成**：init → report.hook==='installed'、hook 文件在、config `hook: true`。更新既有 init 测试（曾断言 hook:false / 无 .git/hooks）。
- **端到端 hook 触发**：临时 git repo → init → 真 `git commit`（hook 自动跑）→ journal 自动多一条该 commit 原子。证明 hook 真装真触发。
- **零侵入**：init + commit 后业务源码 0 改；唯一写 = `.lore/` + `.git/hooks/post-commit`。

## 6. 验收
1. 每 commit 自动留骨架原子（hook 真触发，captureHead 产 commit 原子）。
2. component facet 机械对（路径→code_roots，复用 pathComponent）。
3. 幂等：hook 与 mine 同 commit 去重（按 atom id）。
4. best-effort：hook 失败/坏 repo → exit 0，不阻断 commit。
5. 安装策略 A：不覆盖已有 hook、core.hooksPath/非 git 优雅 skip + 提示。
6. 零依赖零侵入：只写 `.lore/` + 一个 post-commit hook；纯确定性无 LLM。
7. 卸载干净：删 `.lore/` + 摘 hook → 源码原状。

## 7. 不在范围 / 推迟
flow/theme facet · chain 已有 hook · core.hooksPath 安装 · enrich · Stop-hook flush 提醒（§4② note 地盘）· hook 卸载命令（v1 手动摘）。

## 8. 开放问题
- **plugin 路径迁移**：stub 烘焙绝对路径；插件更新移位 → hook 调用失败（`|| true` 不阻断 commit，只是不产原子）。重跑 init 重写 stub。可接受。
- **node 不在 PATH**：git commit 时 node 不可达 → hook 失败（`|| true` 不阻断）。best-effort 可接受。
