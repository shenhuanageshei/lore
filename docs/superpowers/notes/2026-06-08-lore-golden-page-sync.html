component: sync —— 合成总装线

概览

这个模块在干嘛：你写代码、提交（commit），sync 负责把这些变更 整理成一页页给人看的 wiki 文档。它像总装线的调度员——自己不写文档内容， 而是安排好三道工序：先列要更新哪些页 → 让 AI 读源码写正文 → 最后机械收尾盖章。

  1. plan（列工单）：机械扫一遍，列出「哪些页对应的代码动过了、该重写」。
  2. 写正文：AI 读真实源码，写每页的「当前架构」段。（这步要 AI，贵且慢）
  3. finalize（盖章收尾）：纯机械——把决策历史、更新日期、统计数字填进每页页头，再生成索引。（这步零 AI、快）

  fin --> mf[".manifest.json · 诚实 stale"]
  fin --> gr[".graph.json · agent 图谱"]

💡 finalize = 「定稿盖章」那道收尾工序；页头（代码里叫 frontmatter）= 每页最上面那几行元信息（标题、日期、对应的代码版本…）。下面场景会用到这两个词。

为什么要分三道：写正文要 AI（贵），盖章是死规矩（不该用 AI）。分开后， 盖章那道能在你每次 commit 后自动后台跑，正文只在真改了架构时才劳动 AI 重写——省钱省时。

一个场景：「这页文档过时了吗？」lore 怎么诚实回答

lore 给每页悄悄记一个数：「这页正文上次重写时，代码是哪个版本」（一个 commit 号）。
  • 你改几行代码就 commit，但没重写这页正文 → 那个记录的版本号原地不动 → lore 一对比「记录的版本 vs 现在」，差了 3 个 commit → 诚实显示 「这页正文落后 3 个提交，建议重写」。
  • 等你真重写了正文 → 记录的版本号更新到最新 → 「落后」归零。

关键巧思：它只认「正文有没有变」，不认「页头日期、决策历史这些机械刷新」—— 所以盖章那道天天自动跑，也不会假装「正文还新鲜」。

② finalize 数据流 —— 模块内 step-by-step
  1. 读 journal 原子 → foldAtoms 去重 / 丢 amend·rebase orphan
  2. 读旧指纹，逐页：foldJournal 折决策史 → 对折叠后文本算 proseHash → resolveProseSha 定版本号 → stampFrontmatter 盖 code_sha
  3. HOME 同走指纹逻辑；INDEX 纯机械、不进指纹
  4. 写回指纹 + GC 孤儿（只留本轮处理过的页 → 已删页天然丢弃）
  5. 构造 staleScopes：component→[code_root]、flow→spans 各 root
  6. runManifestCli 出 manifest + 写 .graph.json

主体：finalizeSync @ lib/sync.js（读指纹→逐页→HOME→INDEX→写回→staleScopes→manifest）

③ 关键数据契约 —— 状态长什么样

.state/fingerprints.json：

{ "component/sync.md": { "prose_hash": "sha256:…", "prose_sha": "3fbb170" } }
  • prose_hash = 正文哈希，剥掉页头 + 决策史哨兵区 → 只反映 AI 写的架构正文。 改日期 / 决策史 / 状态块都不动它。proseHash @ lib/fingerprint.js
  • prose_sha = 正文上次重写时的 HEAD；页头 code_sha 盖的就是它 → stale = code_sha..HEAD 的 commit 数（按 code_root 限定）。pageEntry @ lib/manifest.js
④ 指纹状态机 —— seed / 保持 / 推进

resolveProseSha @ lib/sync.js（三态：seed / 保持 / 推进）

⑤ 边界 / 坑 —— 改代码前必看
  • 对「折叠后」文本算 hash，不是读入文本：{{LORE_JOURNAL}} token ↔ 哨兵区形态在首次 finalize 跳变；若对读入文本算，seed 后第一次机械刷新会被误判成「正文变了」而错误推进版本号。 注释 @ lib/sync.js（resolveProseSha 上方） ←（A 期实测踩到的坑）
  • 极速连续 commit：两个后台 finalize 可能叠跑 → 幂等全量重建、最后写赢、无锁（YAGNI，spec 决策）。
  • 坏指纹 JSON / 非 git：readFingerprints→{}、reachableShaSet→null → 退化不崩。
⑥ 故障地图 —— 症状 → 定位（debug 从这进）
症状可能原因查哪
某页 stale 一直不归零正文 hash 没变（你以为重写了，其实只动了决策史/页头区）确认改的是「## Current architecture」段；proseHash 剥离范围 @ fingerprint.js
重写正文后 stale 反而变大code_sha 盖成了更旧的 prose_sharesolveProseSha @ sync.js；查指纹 prose_hash 是否真变
决策史重复 / 累积foldJournal 没正确折叠哨兵区foldJournal @ sync.js；查 START/END 哨兵
删了页 stale 还在报指纹孤儿没 GC写回指纹逻辑 @ sync.js（nextFingerprints）
⑦ 测试锚点 —— 改了跑什么
  • test/sync.test.js：「正文不变→prose_sha 保持」「正文改了→前移」「删页 GC」「planSync 增量 / --all」
  • test/fingerprint.test.js：round-trip / 坏 JSON / proseHash 剥离
  • 改 finalize 或指纹逻辑后跑：node --test test/sync.test.js test/fingerprint.test.js
⑧ 不变量 —— debug 的标尺（违反即 bug）
  • 页头 code_sha 恒等于 prose_sha（不再是当前 HEAD）—— 违反 → stale 会撒谎
  • INDEX / docs 轴 永不进指纹（纯机械、永远当前）
  • fingerprints.json 只含本轮处理过的页（已删页天然 GC，无孤儿）
  • finalize 幂等：同输入多次跑，wiki 收敛到同一结果（最后写赢）
  • 正文 hash 只反映「## Current architecture」段，不含页头 / 决策史 / 状态块
