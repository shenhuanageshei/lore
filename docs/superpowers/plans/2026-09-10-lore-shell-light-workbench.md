## 0. 为什么这里没有阶段闸门

设计 §7 的硬约束是「② 的开工条件 = ① 之后 N 周 `confirmed ≥ M`」。本计划**不是 ②**：

- §5.5 是壳自身早已写定的验收项，从未排期，也没被任何闸门约束；
- 它**零新增义务**（不要求 owner 做任何新动作、不产生新的必答确认）；
- 它**不消费理解层数据**（不读 checks / blackbox，不做简报）。

因此本计划可在 ① 期数据积累期间并行推进，不构成对阶段闸门的破例。

## 1. 现状盘点（已实测，非推测）

| 文件 | 行数 | 现状 |
|---|---|---|
| `site/index.html` | 860 | 真正的壳：**187 行内联 CSS**（旧视觉语言，`data-theme` 三档，**默认 dark**）+ 615 行 module 脚本（路由 / 侧栏 / 搜索 / 主题 / sync 控制台 / auto 重写 / 灯箱） |
| `site/shell.mjs` | 368 | **纯函数模型层**（无 DOM），已被 `test/shell.test.js`（503 行）覆盖：markdown 渲染 / 导航模型 / 徽标 / 跨 repo 索引 / 访问传感器 / 预算读数 |
| `site/mermaid.min.js` | — | 本地依赖，不动 |

**依赖事实**：`package.json` 的 `dependencies` 与 `devDependencies` **均为空**，无 jsdom、无打包器。
→ 新增渲染逻辑必须是 `shell.mjs` 里的**纯函数**（Node 可直测），不得依赖 DOM 测试环境。

### 1.1 四条关键事实（决定了本计划的范围）

1. **壳里没有任何「状态行」**。当前 `#topbar` 只有品牌 / 搜索 / 语言 / 主题 / sync 灯。
   设计 §5.3 的底部状态行与 §5.5 的「燃料读数」**完全不存在**。
2. **燃料读数在 API 里不存在**。`GET /api/sync/status`（`server.js:165`）只返回
   `mode / last_finalize / config / runner_running / budget`。
   「决策捕获率」「断流天数」由 `lib/doctor.js` 从 `.lore/journal` + git 派生，
   **只在 CLI 里可见，壳读不到**。→ 必须补数据通道，否则状态行只能显示页数（正是 §5.5 禁止的装饰性遥测）。
3. **决策史在 wiki 里是列表，不是表**。`renderDecisionHistory @ lib/sync.js:162` 产出
   `- **title** — why (sha, date)`；设计 §5.4 要的是**修改记录表**（版本 / 日期 / 变更与原因）。
4. **正文由 JS 在客户端注入的**。`route() @ site/index.html:413-417`：
   `fetch(BASE+'wiki/'+path)` → `renderMarkdown` → `document.getElementById('content').innerHTML = html`。
   **壳是 SPA**——这直接决定了 D9（无 JS 降级）的口径，见 §2。

### 1.2 当前默认主题与设计冲突

壳默认 `dark`（`site/index.html:666`：`localStorage.getItem('lore-theme') || 'dark'`），
设计 §5.1 选定的是**浅色精密工作台**。本计划把默认改为 `light`，**保留** dark / sepia 两档（见 D10）。

### 1.3 壳打开传感器：已接线、但至今零数据

设计 §9 风险 1 把「壳没人开」列为**最上游风险**，对策是「⓪ 期就装壳打开传感器，两周看数据决定去留」。
实测结论（本轮已逐条验证，避免误报）：

- **接线是对的**：`site/index.html:244` import `shell.mjs`，`shell.mjs:358` 模块顶层调用
  `installVisitSensor()`；Node 侧以 `globalThis.location` + stub fetch 复刻浏览器路径实测，
  确实发出 `GET /wiki/.manifest.json` → `POST /api/human/visit`，载荷
  `{"page":"component/runner.md"}`，URL 与 base 推导均正确。
- **服务端也是对的**：以正确 root（`<repo>/.lore`）起 `server.js` 实测，
  `POST /api/human/visit` 落盘 `<repo>/.lore/human/visits.jsonl`，内容
  `{"ts":"…","kind":"visit","page":"component/runner.md"}`。
- **但 `.lore/human/` 从未存在过**（该目录被 `.gitignore:16` 忽略，全盘搜索无任何 `visits.jsonl`）。
  → 结论：机制通，**但 ⓪ 期 S7 的验收「`lore visit` 有数据」从未被真实满足**——
  它只是被单元测试（注入假 `win` + 假 fetch）证明过。这正是设计自己最警惕的失败模式。
- 注：`test/server.test.js:420` 已注明「`createServer(root)` 的 root 就是 `.lore` 目录」；
  `lib/serve.js:219` 传的也正是 `join(cwd,'.lore')`。**根目录传参无 bug**，勿误改。

## 2. 设计决策（实施前钉死）

| # | 决策 | 取值与理由 |
|---|---|---|
| D1 | **字体不得联网** | 原型用 `@import url('https://fonts.googleapis.com/...')`。壳必须遵守 §2 不变量② 的同源精神与 §4 硬约束（无关外部依赖）。→ **不引外链**，只用字体栈：`Inter, system-ui, -apple-system, "Segoe UI", "PingFang SC", "Microsoft YaHei", sans-serif` + `"JetBrains Mono", ui-monospace, SFMono-Regular, Consolas, monospace`。本机装了就用，没装就降级——**不因字体缺失破版**。 |
| D2 | **不新增 API 面** | 燃料读数**并入**既有 `GET /api/sync/status` 的 `fuel` 字段，不新开端点。既有契约「字段只增不改语义」，且壳已有该端点的轮询与降级路径。 |
| D3 | **不重复实现诊法** | `fuel` 的派生必须与 `lore doctor` **同源同口径**（复用 `lib/doctor.js` 的导出与 `UNKNOWN`、`DEFAULT_CAPTURE_WINDOW`），不得在 `server.js` 重写一套。两者漂移即可信度崩塌。 |
| D4 | **检查器面板本期只放锚点** | 原型右侧检查器含「学习进度环 + 一句话自测」——依赖 ④ 期 `checks.jsonl`/`blackbox.jsonl`，**本期无数据源**。→ 本期检查器**只渲染引出线注记**；进度环与自测**不做**，也**不做占位假数据**（§9 风险 4「按钮死亡」）。 |
| D5 | **F5 是浏览器刷新键** | 原型把 `F5` 绑「重写」。真壳里必须 `preventDefault()`，否则点一下就整页重载、打断阅读。**若阶段 D 浏览器实测发现风险不可接受，则 F5 降级为不绑快捷键、只留按钮**，并把结论回填本计划。 |
| D6 | **决策史「版本」列 = 短 sha；无 sha 的原子用 atom id** | §5.4 要求「编号用原子 id + 日期」，否掉的是图号式 `A-04.2`（原型那三行正是被砍形态，**不可照抄**）。实测：525 原子 / 513 提交，**commit 型原子每个 sha 恰好 1 条**（`renderDecisionHistory` 的 `a.commit` 分支天然唯一）；唯一的多原子提交是没有 sha 的 13 条（`commit` 为空）。→ 版本列 = 短 sha（有则用）；**无 sha 的原子以 atom id 兜底**（否则退化成纯日期而撞车）。生成侧改动仅此一处、且只影响无 sha 原子，不制造表格噪音。同时把 atom id 保留在 `title` 属性里，便于对照 `lore confirm <atom-id>`。 |
| D7 | **锚点漂移（本期口径）** | 本期锚点**按生成时刻的 `file:line` 原样渲染**，不做 stale 重解析；注记栏固定显示生成快照语义，**不得静默改写行号**。完整语义定案（行号变动 → 标 stale 还是重解析）**明确留 ② 期**（设计 §7）。 |
| D8 | **F4「检查」绑定检查器** | 本期检查器 = 引出线注记栏（阶段 C 起有内容）。F4 = 聚焦 / 开关检查器；**注释存在时**用 `[` `]` 在注记间跳转。不允许空按钮（阶段 A 的检查器尚无注记 → F4 在无注记时不注册，避免死键）。 |
| D9 | **无 JS 降级：本期只保证静态资产可读** | **诚实口径**：壳是 SPA，正文由 `route()` 客户端注入（§1.1 事实 4）。因此**「无 JS 仍读正文」在本期不可达**，且把正文改服务端渲染是**架构改动**（新增 SSR 路径）+ 与安全注记绑定的重审，**不塞进视觉重做**。→ 本期保证：外壳 DOM（快捷键栏 / 目录容器 / 主区 / 状态行）**静态可读不空白**、样式不依赖 JS、状态行在无 JS 时显示静态读数。**SSR 正文列入 §4「明确不做」并注明理由与归属**。 |
| D10 | **dark / sepia 重映射，不重校** | 两个主题**保留现有色值**，仅把旧变量名映射到 §5.2 的新 token 角色上；本期**只保证不破版**，不做它们的对比度重校（浅色才是 §5.2 的校色对象）。 |
| D11 | **正文 ≤76ch** | §5.3 结构图明文「正文（≤76ch）」。当前 `#content` 是 `max-width:860px`（约百字符）→ 改为 `ch` 单位定宽，并在窄屏复核。 |
| D12 | **语言控件本期保留** | 翻译层删除是设计 §8 判定的**后端**动作（删 `translate.js`/`i18n.js` + config `available:[zh,en]→[zh]`），本期不做；届时一并移除该控件。先删控件会留下「能选但没有」的死状态。 |
| D13 | **状态行读数一律走 `UNKNOWN` 分支** | `fuel` 取不到时不得用 0 冒充（`lib/doctor.js:40-41` 明文纪律）。渲染必须显式支持 unknown 形态：`决策捕获率 unknown · 断流 unknown`。 |
| D14 | **「纯文本导出」不纳入本期交付闸门** | 设计 §5.5 原文是「无 JS / 窄屏 / **纯文本导出**仍能读懂核心内容」。三者中前两项本期做（D9 / 阶段 D）；「纯文本导出」**无现存机制、无既有 CLI**（CLI 对等对的是记录层不是壳渲染），属于独立工作面。→ 本期**显式排除**，并在 §4 记账；**不写进交付判定**（交付闸门引用未测项等于没有闸门）。 |

## 3. 阶段（4 阶段，每阶段含自检命令）

### 阶段 A：视觉地基与结构（纯壳，无新数据）

- **目标**：把 `site/index.html` 的视觉语言从旧 CSS 换成 §5.2 tokens；落**快捷键栏 F1–F5**；
  把 `#topbar` 重组为设计 §5.3 的三段式结构（快捷键栏 / 品牌+搜索+重写 / 主题·语言·sync 灯收纳）。
- **文件**：`site/index.html`
- **验收**：
  1. `:root` 的每个 token 值与设计 §5.2 表**逐值相等**（`#F4F6F9 #FFFFFF #F8FAFC #E2E7EE #CFD7E2 #0F1319 #5B6473 #6B7280 #5B5BD6 #0E7490 #B45309 #15803D #DC2626`）。

  5. **不引入任何外部网络请求**（无 `@import url(https://`、无 CDN 字体/图标）。
  6. 圆角 8–16px、阴影用 §5.2 给定值、动效 `cubic-bezier(.16,1,.3,1)` 150–300ms 且只动 `transform`/`opacity`、尊重 `prefers-reduced-motion`。
  7. 正文列宽按 D11 用 `ch` 定宽（≤76ch）。

### 阶段 C：两个专属视觉（§5.4）
- **目标**：① 源码锚点 = 引出线注记（正文角标 + 右侧注记栏，点角标高亮注记）；
  ② 决策史 = 修改记录表（版本 / 日期 / 变更与原因，版本列按 D6）。
- **文件**：`site/shell.mjs`（新增**纯函数**解析/渲染）、`site/index.html`（挂载与交互）、`test/shell.test.js`
- **渲染位置（评审 #6 澄清）**：壳是 SPA，正文在客户端由 `route()` 注入（§1.1 事实 4），
  故这两个渲染器**是客户端渲染管线的一环**（挂在 `renderMarkdown` 之后、写入 `#content` 之前），
  **不是服务端渲染**。D9 已据此把「无 JS 读正文」排除在本期之外，二者不矛盾。
- **验收**：
  1. 锚点提取：识别正文里 `fn @ file:line` 形态 → 正文插上标角标 `[n]`，右栏按序列出 `fn @ file:line`；同一锚点重复出现**复用同一编号**（不得一号多义或一义多号）。
  2. 点角标 → 对应注记高亮；再点别处取消。
  3. 决策史表：把 `renderDecisionHistory @ lib/sync.js:162` 的 `- **title** — why (sha, date)` 解析为 `{version, date, change}` 三列；**`(sha, date)` 解析失败时降级**（整行进「变更与原因」列、日期列 `—`），**不得丢行**。
  3b. 按 D6：`title` 属性里必须保留 **atom id**（供对照 `lore confirm <atom-id>`）；因此
      `renderDecisionHistory @ lib/sync.js:170` 需**附加** atom id 输出（只对无 sha 原子，避免表格噪音），
      或由壳侧解析时另取——**不得把这个交叉引用静默丢掉**。验收含一条断言：渲染结果里能取到 atom id。
  4. 空决策史（`暂无 journal 原子（跑 /lore:mine 补全）。`）→ 渲染空态提示，**不得渲染出空表头**。
  5. 解析/渲染函数留在 `site/shell.mjs` 且**无 DOM 依赖**（Node 可直测）。
  6. **无锚点 / 无决策史的页不得出现空注记栏或空表**（避免每页挂一堆空壳）。
  7. 按 D7：锚点按生成时行号原样渲染，**不做 stale 重解析、不静默改写行号**。
- **自检**：
  ```
  node --test test/shell.test.js
  ```

## 4. 明确不做（防蔓延）

| 项 | 理由 / 归属 |
|---|---|
| 再入简报 | ② 期主体，有独立阶段闸门 |
