## 1. 背景与定位

### 1.1 外部冲击

智谱 ZCode（GLM-5.3 官方 harness）原生内置「仓库 Wiki」：读一遍代码生成架构导读、结论带源码跳转、支持图表、per-workspace 保存。"读一遍代码给你一份带源码跳转的架构导读"这层价值正在被宿主免费提供。

### 1.2 owner 的真实痛点

1. **答辩断层**：能说出项目是干嘛的，说不出"为什么这么设计""对比过什么方案""怎么保证某性质"。
2. **知识断层**：AI 写代码时用了大量基础计算机 / 软件工程 / 架构知识，owner 不懂——**需要跟 AI 一起成长**。

### 1.3 定位决策

| 方案 | 结论 | 理由 |
|---|---|---|
| wiki 降回物化视图、砍 docs 轴 | 否决 | 那是"和 ZCode 抢生成"的视角；owner 不必用它，harness 会换 |
| 继续做更好的 wiki 生成器 | 否决 | 与免费能力正面竞争 |
| **wiki 保留做厚 + 差异化做 owner 理解层** | 采纳 | 厂商能生成同一份 wiki，拿不到"你懂什么、何时懂的、何时过期" |

> **口径澄清（评审 #6）**："做厚"指模块 / 组件 / 理解层页面；docs 镜像轴降级为索引**不属于**"砍 wiki"，两者不矛盾。

**一句话定位**：lore = 项目的记忆（耐久、可移植、记因果）+ 你自己的理解档案（per-human、可验证、会过期）。

### 1.4 硬约束

无关 harness、无关 LLM provider。推论：多后端链保留（它正是 provider-agnostic 的实现）；理解层不得建立在任何宿主特性上。

## 2. 不变量（8 条，均可写成测试）

| # | 不变量 | 验收 |
|---|---|---|
| ① | **可移植性**：fresh clone + 任意 harness + 任意 LLM，可重建**机械层与记录层**（per-human 层按 ⑥ 独立边界） | 克隆到临时目录、不装插件、不接模型，跑 CLI 出索引 / 体检 / 检索 |
| ② | **无 LLM 降级可用**：机械层产出**通过结构校验**（非空且字段合法），而非"非空" | 断网跑一遍，产物过 schema 校验 |
| ③ | **人的写入不可被机器删改**：append-only；机器可置 `superseded`，但**不得改写内容**，且 superseded 原子在决策史中仍可见 | 重写一轮后比对原子集合：内容字节不变、条目不减 |
| ④ | **CLI 对等**：每条读写路径有一等 CLI；壳 / MCP / hook 只是客户端 | 每个功能都有 `lore <verb>` 形式 |
| ⑤ | **机械层确定性**：无 LLM 重建字节稳定；**哈希输入域显式归一化**（时间戳 / 路径 / 顺序不入哈希或先归一） | 连续重建两次产物 hash 相同 |
| ⑥ | **per-human 边界**（新增）：理解档案独立存储、默认不进公开历史，可导出、可清除 | 开关可验证；导出 / 清除有 CLI |
| ⑦ | **来源诚实**（新增）：机器推断永不冒充人类宣告；无正文不写 why；历史不做 LLM 回填 | 写入侧 lint 会红 |
| ⑧ | **证据锚定 + 不确定性显式**（新增）：面向人的结论必须挂锚点，或显式标「未验证」；未知 / 冲突 / 过期 / 低置信不得渲染成确定事实 | 无锚点的结论进待处理队列 |

> ③ 精确化与 ⑥⑦⑧ 来自评审（见附录 C）。

## 3. 记录层

### 3.1 五类原子 + pitfall

| kind | 用途 |
|---|---|
| `decision` | 采纳的决定 |
| `rejected` | 被否决的方案（负面知识） |
| `correction` | 对自身此前判断的纠错 |
| `question` | 待决问题 |
| `evidence` | 支撑结论的证据 |
| `pitfall` | 踩坑（**字段固定**：`problem` / `fix` / `prevention`，对应现有 CLAUDE.md 的「问题 / 修复 / 预防」三段） |

### 3.2 字段

```json
{"id":"decision:2026-09-09-lore-reposition","kind":"decision",
 "title":"lore 定位：wiki 保留，差异化做 owner 理解层","why":"…",
 "refs":{"supersedes":"…","evidence":["consult:1"],"files":[],"anchors":["runAuto @ lib/runner.js:77"]},
 "source":"agent:dsh","status":"confirmed","confirmed_by":"owner","confirmed_at":"…"}
```

`status`：`draft` | `confirmed` | `disputed` | `superseded`。
**只有 owner 的直接动作能产生 `confirmed`**（agent 代写只能是 `draft`）。

**有效状态 = 派生视图**（① 期 S3 定案，评审 🟡#1）：原子内联 `status` 的字节**永不改写**（不变量③），
「有效状态」由最新一条 `kind:'confirmation'` 记录覆盖内联 `status` 派生——`verdict:'confirm'` → `confirmed`，
`verdict:'dispute'` → `disputed`；无确认记录时回退内联 `status`。确认记录与原子**同源**落在 journal 内
（append-only、可审计），但它**不是原子**：不计入原子数、不进决策史物化（doctor / fold / sync 一律剔除）。
实现：形状与派生在 `lib/confirm.js`，CLI 为 `lore confirm <atom-id> [--why "…"] [--verdict confirm|dispute]`
与 `lore confirm --list`；体检出口是 `lore doctor` 的 `confirm 已确认 N · 待确认 M · 已否决 K` 行。
证据账本（`lore evidence [--json]`，`lib/evidence.js`）按同一份派生列账：缺 `refs.anchors` 标「未验证」（不变量⑧），
噪音 `high` 标「低置信」（与 doctor 同源分类器）；只读，`--json` 不含 `.lore/human/` 的 per-human 内容。

### 3.3 per-human 记录（评审 #1 补齐）

| 产物 | 存储 | CLI |
|---|---|---|
| 已阅 @ 版本戳 | `.lore/human/read.jsonl` | `lore read <page> --at <sha>` |
| 黑盒自评（修正用，默认机械推导） | `.lore/human/blackbox.jsonl` | `lore blackbox <module> --level 懂\|半懂\|黑盒` |
| 阅读痕迹（page-open） | `.lore/human/visits.jsonl` | `lore visit <page>`（壳调用） |
| 理解检查记录 | `.lore/human/checks.jsonl` | `lore check <page>` |

边界：**默认不进 git**（⑥）；`.lore/human/` 进 `.gitignore`，`lore human export` 可导出为可移植格式。**注意**：这与"理解档案是护城河"并不冲突——护城河是"这份数据存在且属于你"，不是"必须公开"。

### 3.4 写入侧纪律（升级为不变量 ⑦ + lint）

- 不落 trailer-only 的 why（**口径**：剥掉 trailer 后为空 → 127 条，见附录 B）。
- 历史 127 条**不做 LLM 回填**（伪造因果史比空白更有害）。
- `stripTrailers` 从渲染侧前移到写入侧（现成：`lib/fold.js:72`、`lib/mine.js:7`）。
- **必须做成会红的测试**，否则就是约定，约定必腐（评审意见）。

### 3.5 已知断线（评审实测）

`.lore/config.yml` 声明 `mine: [commits, changelog, claude_md_pitfalls]`，但 `lib/mine.js:50` 只写 `kind:'commit'`、`lib/mine.js:56` 硬编码 `pitfall:null`——**踩坑挖掘这条声明路径是死的**。与"hook 断流 3 个月"同型：**声明了 ≠ 接上电**。⓪ 期必须接线或摘掉声明。

### 3.6 两个被评审点名的术语（先定义再排期）

- **agent 代捕获约定**：在 CLAUDE.md / AGENTS.md 的 resident 区块里加一条规则——"做出非显然决策时，追加一条 `kind:decision` 的 **draft** 原子（附 `why` 与源码锚点）"，并给出 `lore note --draft` 的 CLI 示例。它是**指令文件 + CLI 的标准约定**，不依赖任何宿主特性。
- **成本账本**：每次 LLM 调用追加一行 `{ts, page, backend, tokens, ms, ok}` 到 `.lore/.state/cost.ndjson`（per-machine、gitignored）；**预算上限** = 每版本上限，维度 `tokens|calls|ms`（后端不回报 token 数时回退 `calls`），超限则自动档不启动、原因经 `/api/sync/status` 与壳状态行可见。账本只记录会变成验尸报告，**必须配预算闸**。

## 4. 理解层（v2 重排）

> 原则不变：**阅读不产生理解，检索练习才产生**——但这条本身是假设，其被动版本才是默认产品（见 4.4）。

### 4.1 再入简报（**第一条端到端切片**）

离开 N 天回来，一页给到：期间哪些模块动了（附改动量）/ 以前确认过的东西哪些过期了 / 先读哪三页 / 黑盒模块周边变了什么。

- **纯派生**：确认记录 × 期间 churn × 新决策原子 × 黑盒清单。
- **输入全部机械默认**（评审要求）：黑盒默认 = 从未打开 × 高 churn；已阅默认 = 打开即记；不依赖 owner 自评。
- 验收：用 2026-06-13→09-08 的**真实 85 天断流期**做夹具，或 CLI 支持 `--as-of`——不用等日历。

### 4.2 答辩准备（**事件驱动，非常驻页**）

`lore prep` 按需生成：5 组（一致性 / 性能 / 可用性 / 可扩展性 / 取舍）× 5 题 + 追问链；答案四段式：**结论 → 机制 → 数字 / 证据 → 反方案对比**。必答狠题："你怎么保证 X 性"、"这个设计最脆弱的假设是什么"（后者直接摆数据自曝）。

> 评审一致意见：静态题库三个月就腐，改成"owner 说两周后要答辩才烧这把钱"。

### 4.3 理解检查（取代"自测"，**任务式**）

不是选择题，而是"给场景、定位入口、解释决策、指出风险"，记录答案 + 证据 + 是否正确。

- **默认被动模式**：只记阅读痕迹 / 出简报 / 提醒过期，不提问。
- 主动检查是 **opt-in 实验**，带死亡条款（30 天低于阈值 → 永久降级为被动）。
- **不与"确认"耦合**：确认挂在最便宜的动作上（读页即打「已阅 @ 版本」、stale 徽标一键确认）。
- 理解的可观察定义（评审给出）：能否找到入口 / 能否解释一个关键决策 / 能否预测一个改动影响 / 故障时能否找到下一步。

### 4.4 黑盒地图 + 阅读痕迹

- 壳记 page-open（一行代码）→ 同时喂 wiki 健康度（90 天零打开 → 索引化候选）与理解游标。
- 自评是**修正手段**，不是数据来源。

### 4.5 版本切分

`version.mode: auto | tag | tag-first`。**聚类必须确定性**（稳定排序、不读挂钟），否则违反不变量 ⑤。需要人宣告的机制必须有环境默认。

### 4.6 砍掉 / 折进（评审结论）

| 原方案 | 处置 | 理由 |
|---|---|---|
| 能力地图（独立产物） | **砍** | 它映射的是**项目**不是**人**（约等于读一份聪明的 package.json）；违反"阅读不产生理解"；静态策展会烂。深度分档 rubric 折进 4.3 的检查记录 |
| 决策思维卡（独立产物） | **砍**，四段式折进 `why` 的 schema 模板 | `why` 字段本身就是思维卡；单独做要么是 LLM 回填（3.4 禁止），要么是重排版 |
| 自测出题引擎 | **砍**，留台账 + 被动模式 | 出题者 = 判卷者 = LLM，"验证"的客观性增益为零；黑盒自评已零成本拿到同一份自报信号 |

## 5. 壳设计

### 5.1 方向

**浅色精密工作台**（owner 选定）。深色玻璃拟态被否（装饰感、像通用 AI 产品）；纸本杂志风被否（书 ≠ 工具）。视觉语言从工程师身边的真实物件借：终端状态行、图纸引出线、工程修改记录表。

### 5.2 设计 tokens

| 角色 | 值 |
|---|---|
| 画布 / 面板 / 次级 | `#F4F6F9` / `#FFFFFF` / `#F8FAFC` |
| 边框 / 强调边框 | `#E2E7EE` / `#CFD7E2` |
| 正文 / 次要 / **弱（已修）** | `#0F1319` / `#5B6473`（5.97:1）/ **`#6B7280`（4.83:1）** |
| 主色 / 副色 | `#5B5BD6` / `#0E7490` |
| 陈旧 / 成功 / 危险 | `#B45309` / `#15803D` / `#DC2626` |
| 字体 | Inter 13.5px/1.66 + JetBrains Mono（读数 / 锚点 / 日期）+ 中文回退 PingFang SC / 微软雅黑 |
| 圆角 / 阴影 | 8–16px / `0 1px 2px rgba(16,24,40,.05), 0 24px 48px -28px rgba(16,24,40,.22)` |
| 动效 | `cubic-bezier(.16,1,.3,1)`，150–300ms，只动 transform/opacity，尊重 `prefers-reduced-motion` |

> 修正：v1 的"弱"色 `#8A94A3` 在白底仅 3.07:1，违反本文件自己的 ≥4.5:1 要求（评审 #11），已换为 `#6B7280`。

### 5.3 结构

```
┌ 快捷键栏 F1 Wiki · F2 检索 · F3 决策史 · F4 检查 · F5 重写 ─────────┐
│ 品牌 │ 搜索 │ 重写这页                                              │
├──────────┬────────────────────────────────────┬──────────────────┤
│ 目录树   │ 正文（≤76ch）                      │ 检查器           │
│ 分组+计数│ 面包屑 / 标题 / 摘要 / 状态 chips  │ 理解进度环       │
│          │ callout / 流程图 / 机制详解折叠     │ 引出线注记       │
│          │ 修改记录表 / 源码锚点               │ 一句话检查       │
├──────────┴────────────────────────────────────┴──────────────────┤
│ CAPTURE OK · 决策捕获率 38% · 断流 0 天 · 94 页 · 队列 2 · 14:02  │
└──────────────────────────────────────────────────────────────────┘
```

### 5.4 两个专属视觉

1. **源码锚点 = 引出线注记**：正文角标 + 右侧注记栏（`runAuto @ lib/runner.js:77`），点角标高亮注记。
2. **决策史 = 修改记录表**：`版本 / 日期 / 变更与原因`。**编号用短 sha；无 sha 的原子用原子 id 兜底，日期单列**（评审否掉图号式 `A-04.2`：多养一套编号空间无收益）。
   > 口径修订（2026-09-10，壳实施期实测）：原稿写「编号用原子 id + 日期」，实施时实测 525 原子 / 513 提交——
   > commit 型原子每个 sha 恰好 1 条（天然唯一），而唯一的多原子提交（13 条）**全都没有 sha**。
   > 故版本列取「有 sha 用短 sha，无 sha 用原子 id」，日期独立成列；原子 id 另挂 `title` 属性，
   > 供对照 `lore confirm <atom-id>`。理由与取舍见 `plans/2026-09-10-lore-shell-light-workbench.md` 的 D6。

### 5.5 壳的验收（评审新增）

- **状态行必须可操作**：显示"队列 2"就能点进去看并修复，否则是装饰性遥测。
- **状态行显示燃料读数**：决策捕获率、断流天数——这是产品生死攸关的数，不能只显示页数。
- **锚点漂移语义**：源码行号变动后，锚点标 stale 还是重解析，必须有明确行为。
- **降级**：**无 JS 时外壳非空白且状态行可读**（正文不可读属本期已知限制）；窄屏隐藏检查器、折叠目录、保留状态行。
  > 口径修订（2026-09-10，壳实施期实测）：原稿写「无 JS / 窄屏 / **纯文本导出**仍能读懂核心内容」，
  > 被两道实施决策收窄，本行按落地口径改写（**收窄不是放弃，两项都在计划的「明确不做」与交付判定里记账**）：
  > ① 「无 JS 也能读正文」在本期**不可达**——壳是 SPA，正文由 `route()` 在客户端注入，
  >    改服务端渲染是架构改动（新增 SSR 路径 + 与 `shell.mjs` 安全注记绑定的重审）；本期只保证
  >    外壳 DOM（快捷键栏 / 目录容器 / 主区 / 状态行）静态可读不空白；
  > ② 「**纯文本导出**」**排除出本期交付闸门**——无现存机制、无既有 CLI（CLI 对等对的是记录层不是壳渲染），
  >    属独立工作面。两者详见 `plans/2026-09-10-lore-shell-light-workbench.md` 的 D9 / D14 与 §4、§6。

## 7. 分期（v2 重排）

| 期 | 内容 | 验收（可今天跑） |
|---|---|---|
| **⓪ 数据与证据地基** | 五类 + pitfall 的**完整 schema**；写入侧纪律 + 会红的 lint；agent 代捕获约定 **+ 捕获召回率闸门**；**壳打开传感器**（一行代码，最便宜的 go/no-go）；per-human 存储边界与 CLI（`lore check` 的 verb 延后至 ④，⓪ 只落存储）；成本账本**定义 + 预算上限（tokens/calls/ms）**；接线或摘掉 `claude_md_pitfalls` 死声明 | 新提交的 why 无 trailer-only；下 N 个提交中 ≥X% 的真实决策落成原子（**per-backend 测试矩阵**）；`lore visit` 有数据 |
| **① 证据清洗与确认** | 噪音分类器（trailer / 模板 / 重复摘要降权）；`lore confirm` + 已阅 @ 版本；证据账本（结论 / 来源 / 定位 / 时间 / 置信 / 确认人） | 每条决策可在裸终端确认；机器重写不改人的原子 |
| **② 一条端到端理解切片** | 再入简报 + 证据 + 一个模块，端到端打通；**锚点漂移语义**（行号变动 → 标 stale 还是重解析）在本期定案 | 用 85 天断流期夹具或 `--as-of`，10 分钟内回答"它做什么 / 为何这样 / 哪里会错 / 证据在哪" |
| **③ 机械化扩展** | docs 索引化 + 痛点雷达 + digest 骨架 + auto 追版本 + 版本切分 | 无 LLM 产物过 schema 校验；版本切分可复现（不变量 ⑤） |
| **④ 理解检查与回归** | 任务式检查（opt-in，带死亡条款）+ 变更影响回归（源码 / 决策变化后哪些卡片失效） | 关闭检查后被动模式仍可用；失效项可追踪 |
| **⑤ 答辩与扩展** | `lore prep` 事件驱动 + 持续答辩（不等最后） | 每组答案带出处 |

**硬约束**：捕获与确认必须先于消费类功能——瓶颈是日历时间不是工程时间（实证：85 提交零原子）。
**阶段闸门**：② 的开工条件 = ① 之后 N 周 `confirmed ≥ M`（N、M 在开工前定死）。

## 9. 风险（v2 排序）

1. **壳没人开（最上游）**：理解层的唯一传感器是 page-open。若 owner 在 IDE 里看代码、几周不开壳 → 黑盒空、痕迹空、检查无宿主、简报退化成 changelog 精简版，护城河塌缩。**对策：⓪ 期就装壳打开传感器，两周看数据决定去留。**
2. **燃料断流**：清洗只治存量；增量靠"agent 代捕获"。但**约定不是解药，约定就是病因**（85 提交零原子、490 原子 1 决策）——必须配**捕获召回率闸门**，否则 ②③④⑤ 全建在一台没验证过的泵上。
3. **确认通胀**：全自报、无外部真值。对策：确认绑版本、可机械判过期、显示推翻率、不 gamify。
4. **按钮死亡**：owner 行为数据（note 1 / 翻译 0 / enrich 1）证明不做可选动作。对策：被动优先、确认挂最便宜动作、预立死亡条款（推广到全部理解层产物）。
5. **n=1 的护城河**：per-human 数据的价值目前只有单用户证据；团队价值未验证。
